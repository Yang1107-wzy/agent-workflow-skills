# Professional Workflows Implementation Plan

Architecture: five portable independent skill folders, each with a focused Python helper and a reference contract. Existing installer, bundle validator and package builder discover all folders. Parent owns shared docs/packaging/CI; each implementer owns only its assigned skill, tests and fixture subdirectory.

## Global Constraints

Python >=3.10; zero runtime third-party dependencies; UTF-8 I/O; documented exit codes; public examples synthetic. Scripts never mutate input files or overwrite output files. No sending messages/calendar tickets or external writes except separate user authorization. Each skill must have unit/subprocess failure regressions and an isolated forward user-task evaluation. Skill name matches folder; all local references resolve inside that skill; installed folders must work without sibling skills.

### Task 1: Meeting notes to actions

Ownership: skills/workflow-meeting-actions/**, tests/test_meeting_actions.py, examples/meeting-actions/**.
Helper: scripts/validate_actions.py ACTIONS_JSON TRANSCRIPT [--format json|text]. Exit 0: structure/evidence valid, unresolved items allowed; 1: invalid claims/evidence; 2: usage/I/O/JSON errors. Read-only.
Schema: root schema_version=1, meeting={date:null|string ISO,timezone:null|string}, actions array. Each action id (unique nonempty string), action (nonempty text), status (committed|proposed), owner (nonempty string|null), due_text (nonempty string|null), due_date (ISO|null), resolution_basis (nonempty string|null), source={start_line:int,end_line:int,quote:string}. Exact quote occurs in indicated line span. Start/end integers exclude bool, positive in range, end>=start. Null owner/due_date become review items. A date with a relative/unspecified due phrase needs meeting date, timezone and resolution basis; explicit ISO dates in due_text may be used without meeting context. Validate Gregorian date syntax and canonical YYYY-MM-DD. Do not parse ambiguous natural language in the helper.
Tests before code: quoted evidence mismatch, invalid line bounds, unknown owner/date allowed, unsupported resolved relative date rejected, duplicate IDs, malformed JSON and source unchanged. Then implement, document, run focused tests and lint, commit only owned files. Self-review and report exact RED/GREEN commands. Synthetic transcript includes named commitment with explicit date, general discussion, concrete proposed task with unassigned owner and a commitment with no deadline. Agent-produced actions.md and review.md complete the workflow.

### Task 2: Experiment result reporting

Ownership: skills/workflow-experiment-report/**, tests/test_experiment_report.py, examples/experiment-report/**.
Helper: scripts/summarize_results.py RESULTS_JSONL --metric NAME --expected-cases N --unit UNIT --protocol LABEL [--format json|markdown]. One object per row with unique nonempty string/integer id excluding bool; metric finite int/float or null for explicit failed result; explicit expected-cases>=row count and >0. Missing metric, invalid JSON, duplicate IDs/nonfinite/unsupported numeric precision return 2; zero available measurements still returns a usable report with null mean and explicit coverage 0. No silent row dropping. Record source hash, counts observed/expected/returned/failed/missing, conditional mean/median/min/max, and raw metric key/unit/protocol. Reject unsafe float parsing that changes decimal digits; include zero/negative measurements as valid. Population summaries, no uncertainty or significance claims. Markdown output never calls missing returns successful.
Tests before code: coverage with null/missing expected cases, true zero value, duplicate IDs, booleans/nonfinite metric, precision loss, all failed, source unchanged. Workflow produces summary.json and experiment-report.md with methodology/denominator distinctions, source/protocol definitions and limitations. Comparisons require matching protocol/unit/denominator conditions; do not fabricate new runs.

### Task 3: Project documentation synchronization

Ownership: skills/workflow-docs-sync/**, tests/test_docs_sync.py, examples/docs-sync/**.
Helper: scripts/change_manifest.py REPOSITORY --base COMMIT --head COMMIT. Resolve explicit revisions as commits, disallow flag injection. Return schema version, resolved base/head, changed status/path entries including renamed old paths, tracked/untracked dirty status, and candidate doc paths from known README/docs/CONTRIBUTING/changelog conventions. Read-only Git subprocess argv, UTF-8 with deliberate raw-name handling; no remote operations. Changes restricted to supplied commits; do not silently include the dirty worktree in that diff. Unborn/missing commit/repo returns 2, empty diff valid. Name candidate docs as suggestions, not verified impact analysis.
Tests before code: temporary Git repository change, rename/delete, invalid revision, empty diff, dirty/untracked visibility, Unicode names, source unchanged. Workflow inspects relevant code and existing docs, writes docs-sync-plan.md and edits authorized affected docs, runs documented command examples appropriately, produces docs-sync-report.md with evidence and remaining mismatches. Respect existing generated-doc convention; do not overwrite generated artifacts manually.

### Task 4: Small-package release preparation

Ownership: skills/workflow-release-prep/**, tests/test_release_prep.py, examples/release-prep/**.
Helper: scripts/prepare_release.py ROOT --version VERSION --artifact RELATIVE_PATH (repeat) [--format json|markdown]. Read pyproject.toml project.version or package.json version when present; Python3.10 cannot rely on tomllib, use a narrow documented literal parser rejecting ambiguous project metadata rather than claiming general TOML support. Generic explicit version supported if no manifest. Require semver MAJOR.MINOR.PATCH (optional documented prerelease allowed only if implemented/tested), selected artifacts ordinary contained nonsymlink files, no directories or escaping traversal, nonempty bytes; hash SHA256. Changelog section must mention requested version, manifest version matches. Report readiness issues (exit1), usage/I/O malformed metadata (exit2), valid local readiness (exit0); distinguish checks not run (tests/build/remote CI/publication). If Git repository available report commit/dirty state; dirty means not locally ready; generic nongit folder can report version/artifact readiness with provenance not checked rather than fabricate commit.
Tests before code: matching version/changelog/artifact hashes, mismatch, missing artifact, escaping path/symlink, empty artifact, dirty Git root, generic project, malformed/ambiguous version. Workflow verifies actual checks for selected source, produces release-notes.md, release-checklist.md and SHA256SUMS without overwriting originals. Publishing only when authorized and only after concrete assets/checks; never imply uploaded merely because prepared.

### Task 5: Bilingual professional editing

Ownership: skills/workflow-bilingual-edit/**, tests/test_bilingual_edit.py, examples/bilingual-edit/**.
Helper: scripts/check_preservation.py SOURCE EDITED MAP_JSON [--format json|text]. Map schema_version=1, items with unique id, source (nonempty literal), target (nonempty literal), kind (number|date|name|status|term|other). Check source literal exists, target literal exists, compare literal occurrence counts so accidental duplicate/drop is visible; explicit same literal accepted. Output issues/review evidence only; do not certify paraphrase/translation fidelity. Empty map invalid; UTF-8, inputs unchanged; malformed/unknown kind map returns2, detected missing/count issue1, structural literal preservation0. User-authorized factual changes represented by an explicit explanation in map rather than silently treated as editing; document semantic review of approval/status and units regardless of literal pass.
Tests before code: successful Chinese-English mapped named entity, missing numeric anchor, extra duplicated target, stale source anchor, duplicate map IDs, invalid schema/empty map, source unchanged. Workflow outputs final edited document, preservation-map.json, editing-notes.md preserving facts/hedging/research stage and terminology. Use native document tools for requested Word/PDF/LaTeX; helper does not render.
